# 独立战斗状态面板

双击 `打开战斗面板.vbs` 即可打开 Tkinter 窗口并自动开始只读轮询，启动和后台 ADB 子进程均不显示黑色控制台。命令行也可运行 `python main.py [--serial DEVICE_SERIAL] [--package ANDROID_PACKAGE]`；不提供 serial 时只在 `adb devices` 恰好有一个在线设备时自动连接，需要追加参数时仍可用 `打开战斗面板.cmd --serial ... --package ...`。CMD 入口本身可能短暂出现命令窗口，VBS 入口用于无控制台双击启动。启动器查找 `pythonw.exe`、`pyw.exe` 和当前用户下已存在的 bundled Python，不安装依赖。

读取器每帧重新绑定 PID、startTicks、executable、manager、BattleId、回合和映射表。经验证的 manager 地址按 serial、包名和进程身份缓存在当前用户缓存目录；首次定位成功后，同一进程后续只验证 manager 与需要的角色表/对象，不重扫整段内存。游戏重启后进程身份改变，会重新定位 manager。

窗口左右并列显示“本方”和“对方”，每侧的主单位与宠物分别成列，各自从上到下排五槽，共二十张卡片同时可见。槽位顺序沿用 `initRolePos` 中各列的位置顺序。位置 ID 使用实际映射编码；本地角色所属的已确认位置族用于确定两侧。两侧各自保留站位顺序与卡片状态。孩子角色属于单独的第三组，不在任一侧这十槽范围内。没有映射的站位显示为空槽；死亡角色保留站位并标为死亡；已映射角色身份或 HP/MP/Speed 读取异常时整帧作废并显示错误。SP 标签表示 `m_Speed`（速度）。单位名称未确认。

站位依据 `initRolePos` 两侧主单位与宠物各五个固定 position ID，并由当前本地角色位置决定对向一侧。为采用竖向阵列并让双方二十项同时可见，界面将每侧主位和宠物位各排成一列、每列五行；卡片顺序沿用游戏位置顺序，位置 ID 保留实际映射值。卡片位置用于查看，不代表游戏中的屏幕坐标。该工具是独立应用，不会自动启动或集成到 WPE 主程序。所有读取均为只读 ADB `/proc` 访问，不调用游戏方法、不暂停、不注入、不写进程内存、不发包；本地客户端数值不代表服务器确认。

双侧扩展前的单侧版本实测单次读取约 1.6 秒，读取完成后等待 1.5 秒再更新；双侧版本尚未重新测量。缓存只在相同游戏进程内复用；游戏重启或缓存失效时首次定位可能较慢。读取失败会清除旧属性显示，保留最后确认的站位。
