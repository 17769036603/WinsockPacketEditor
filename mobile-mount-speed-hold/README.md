# 角色速度保持（Android 模拟器）

这是独立的 x86_64 Android 应用，包名为 `com.xnas.wpe.mounthold`。目标速度默认 5000，来自本机 WPE 数据库中名称精确为“坐骑速度保持”的单条指令。APK 与桌面预设独立保存，不建立同步关系。

当前 APK 保持本地角色的 `m_RoleMoveSpeed`，不要求骑乘，也不依赖 `m_RideId` 字段。首次定位仍要求唯一的本地角色和有效玩家编号；定位后缓存命中时不再因玩家编号变化触发重扫，但每轮仍确认本地角色标记、进程、字段位置和速度值。点击“启动保持”开启，停止时按已保存的原值安全恢复。

Activity 负责选择目标游戏包名和读取目标速度，并在首次启动时申请“显示在其他应用上层”权限；成功发起前台服务后，主面板自动移到后台。Java 前台服务只显示一个可拖动的圆形悬浮球：运行中显示绿色“运行中”，异常时显示红色“异常”，未运行时保留原有颜色和“速”字；长按满 3 秒请求 Rust 安全恢复，恢复结束后服务自动关闭。通知可重新打开主面板。角色发现、校验、写入、journal 和恢复由 `rust-reader` 中的 Rust worker 实现。包名选项严格沿用 hold 预设的 `com.gdoo.dhxy` 默认值与 `com.gdoo.xxxy2026` 专用 fallback。

Rust worker 意外退出后，前台服务会保留红色异常状态并按 1、2、4、8、16、30 秒退避持续自动重试；worker 报告 `holding_speed` 后重置退避。Android 回收服务进程时，系统会携带最近的启动或停止请求重建前台服务。若恢复记录被阻止，或 worker 报错但未确认恢复，服务暂停自动重试并保留错误提示。用户长按停止后，服务会继续 Rust 安全恢复流程；确认恢复后才关闭服务。

运行诊断日志以 JSONL 写入应用私有目录 `files/logs/mount-hold.jsonl`，记录服务和 worker 启停、状态变化、退出码、重试间隔及恢复结果。重复的写入核验状态最多每 30 秒汇总一次。当前文件上限 1 MiB，另保留 3 个轮转文件（`.1` 至 `.3`）；卸载应用会删除这些日志。可在已授权 Root 的模拟器上通过 `adb shell su -c "cat /data/user/0/com.xnas.wpe.mounthold/files/logs/mount-hold.jsonl"` 查看当前文件。错误详情只保留受限类别，日志不记录 PID、内存地址或原始 TValue；Rust stderr 原文仍不保存。

刷新汇总分别记录缓存命中、已知表扫描和全内存发现的次数及平均/最大耗时；`fullScanCount` 保留为后两者的总数。缓存回退事件只写入固定的回退路径和原因类别，便于区分表内重新扫描与全内存发现，不记录动态错误文本。

缓存命中时若 m_IsLocalPlayer 暂时读到 false，先等待 50 ms 和 100 ms，每次清除本轮页缓存后重读，最多额外等待 150 ms；仍未确认时丢弃缓存并沿用已知表刷新与全内存发现，身份未确认前不写入。表移动等其他错误沿用原刷新路径。全内存发现使用批量表头读取和目标字段节点索引筛选表，保留外链或无法安全排除的表，再执行完整字段、当前角色及候选唯一性校验。页缓存不跨轮保留，日志格式沿用现有刷新路径与耗时统计。

新恢复记录使用 `role-speed-hold-v2`，按角色绑定；旧 `mount-hold-v1` 记录仍可读取，但恢复时必须保持原角色表及速度地址匹配，无法确认时保留记录。包名、私有目录、日志路径保持原值，覆盖安装保留设置；回退旧 APK 前应先在新版停止并完成恢复。

使用时选目标游戏包名、输入速度并启动即可，不需要手动填写 PID；worker 会在运行时定位该包当前的进程身份。模拟器需提供 su Root 和悬浮窗权限。若应用升级后发现上次遗留的 journal 对应进程已消失或已被替换，worker 会先将原 journal 原样归档，再重新查找游戏；归档文件会保留，不会自动清理。若旧进程身份仍存在但与当前选择的包名不符，worker 会停止并保留 journal，需切回原包或结束旧游戏进程后重试。

构建：在此目录运行 `gradlew.bat assembleDebug`。产物为 `app/build/outputs/apk/debug/app-debug.apk`。首版只打包 `x86_64`，面向当前 Android 模拟器构建流程。
