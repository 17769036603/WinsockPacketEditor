# WPE Battle Panel

独立的 Android 战斗观察面板，与桌面 WPE MobileSync 控制端分开安装。界面使用原生 Java，Rust worker 在 Android 本地只读读取当前游戏战斗数据，并在悬浮窗内显示本方与对方各十槽、共二十槽的 HP、MP、SP。SP 优先使用战斗角色 `m_Speed`；字段缺失时仅对已绑定的本方角色读取客户端属性值，战斗增减速后的最终速度未确认。

当前目标设备为 Android 14 / x86_64。进程内存读取需要在模拟器上由用户明确授予应用 Root 访问；普通 ADB shell 或桌面读取成功不表示应用已获得该权限。

## 构建

需要 Android SDK 35、Android NDK、Rust stable 和 Windows PowerShell。先安装 Rust Android target：

```powershell
rustup target add x86_64-linux-android
```

从本目录构建 debug APK：

```powershell
.\gradlew.bat assembleDebug
```

构建会先编译 `rust-reader`，再把 worker 打入 APK。默认输出路径为 `app/build/outputs/apk/debug/app-debug.apk`。EBP2 双侧版本已在 Android 14 x86_64 `emulator-5554` 安装并以 Root 启动；实战第 1 回合确认本方、对方人物与宠物四列同时显示 HP/MP/SP，槽位从上到下为 5→1。当前只确认这一回合的实时帧；跨回合刷新和游戏进程重启后的冷定位仍待验收。

## 使用

启动前可选择 `com.gdoo.xxxy2026` 或 `com.gdoo.dhxy`，选择会自动保存；正在读取时需先停止面板才能切换。两个游戏使用独立候选地址缓存，避免读取后台的另一个游戏。冷定位先寻找管理字段和对应节点，再保留关联的表头，避免无关表头耗尽扫描上限。

没有可验证的 SP 来源时显示“—”。属性缓存按每帧当前角色 ID 绑定并复核；对方单位以及伙伴缺少 type 52 属性记录时保持未知。SP 属性值不代表战斗增减速后的最终速度。槽位状态与失败处理边界见 [PROTOCOL.md](PROTOCOL.md)。

安装 APK 后打开应用，按提示允许悬浮窗和通知。首次启动读取器时，应用会先等待 Root 管理器完成授权，再显示带扫描进度或读取状态的悬浮面板。拒绝或系统不支持时会显示权限状态并清除数据。面板显示双方各十槽：横屏对方在左、本方在右；对方人物在左、宠物在右，本方宠物在左、人物在右；窄屏可纵向滚动。四列均从上到下显示槽位 5→1。空槽、死亡和非实时状态不会以 0 伪装成有效数值。

HP/MP/SP 读取器只读访问目标进程，不写内存、不注入、不发包；新增抗性页通过下面说明的独立短时查询通道获取数据。应用私有缓存保存版本化的 manager 候选地址，绑定 package、PID、startTicks 和 executable；只有完整样本读取成功后才写入缓存，每次复用前重新验证。旧缓存版本会被忽略。冷发现会验证管理表字段、位置表和双方二十槽角色结构；失败后按 2、4、8、16、30 秒间隔重试。战斗、回合或映射在单帧读取中变化时丢弃该帧。EBP2 帧使用 40 字节头部和二十个 32 字节槽位，载荷严格为 680 字节，最大载荷限制为 1024 字节；协议细节见 PROTOCOL.md。进程重启后的冷定位仍待设备验收。

## 抗性页（0.2.1）

打开底部“抗性”页后，上方选择抗混乱、抗毒、抗昏睡、抗封印、抗风、抗雷、抗水、抗火、抗震慑、抗三尸、抗鬼火、抗遗忘或物理吸收。下方沿用属性页的四块表格，同时显示双方人物和宠物二十个位置的所选抗性；槽位从上到下为5→1。横屏对方在左、本方在右，窄屏纵向排列；切换抗性只切换显示，不重新查询。结果是本场查询快照，标明发起回合；每场最多查询一次，换战斗或失去有效战斗帧即清除旧值。缺失字段显示“未提供”，零和负数原样按百分比换算显示。

该通道仅支持当前已验证的 `com.gdoo.dhxy` / Android x86_64 Root 环境。它使用已有 FridaCore 和 Java/Lua 桥临时进入游戏线程，调用 `C2S_GetRolePro` 并接收 `S2C_GetRolePro`；转发原响应处理，收到响应或超时后恢复观察。不会修改角色属性，也不改变独立战斗快进 APK。原 EBP2 固定 680 字节协议保持不变。角色返回值按同一进程启动身份、战斗、角色对象与位置绑定；孩子不是现有二十槽的一部分，绑定确认后忽略。

查询用 Rust 模块为 `resistance-query-rust`，Gradle 会同时调用 `build-resistance-query.ps1`。它复用已安装的 Frida core-devkit 17.17.0 Android x86_64，位置为工作区 `.scratch/frida-core-devkit-17.17.0-android-x86_64`；不新增下载或常驻 frida-server。构建机器需要已登记的 NDK 27.2.12479018。

服务停止后丢弃未完成结果，已经进入游戏线程的临时观察自行限时恢复。查询失败会显示原因；本场不重复发送，下场在抗性页保持展开时重新查询。普通属性页面的数值、战斗查询结果和服务器最终计算结果可能不同，此页不保证展示最终战斗计算值，也没有接入未确认的编号或对方 SP。
