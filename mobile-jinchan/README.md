# 金蟾装备助手

独立包名 `com.xnas.wpe.jinchan`，版本 `0.2.0`，适配 x86_64 Root 模拟器。界面可选择 DHXY（`com.gdoo.dhxy`）或 XXXY 2026（`com.gdoo.xxxy2026`）。与飘渺助手和战斗快进分开安装。

金蟾业务目前只在 DHXY 版验证。XXXY 2026 当前运行态的 `JinChanMgr` 缺失，查询会明确失败，不能把连接成功当作业务兼容。

打开助手会连接选中的游戏并返回游戏。连接成功后由 Android 前台服务保持 Rust worker 和同一 Frida 会话；再次回到助手查看结果时不会重复连接。界面显示连接状态，提供连接和断开按钮。首次附加失败会显示真实错误，需要手动重连；保持连接不保证首次附加一定成功。退出或重启游戏会使旧连接失效，助手进程结束时 worker 也会释放连接。

选择部位，点击“查询 / 刷新”；提交后自动返回游戏，让游戏线程处理请求。保持游戏前台，操作完成后回助手查看服务器候选，再选择基础与炼化组合。生成和归还分别确认；归还会删除当前金蟾装备。生成实测消耗 100000 普通仙玉，结果展示背包与货币变化。

每次操作复用会话，单独加载和卸载桥接脚本，并检查临时 Lua 观察器恢复。操作串行，超时不自动重发。未确认清理会阻止继续操作，不能直接清除锁后叠加。候选绑定游戏、连接、角色、部位及内容，五分钟过期；换游戏、连接或部位后重新查询。首次需要授予 Root。前台服务通知显示连接状态；失败诊断保存在应用私有目录的 `jinchan-daemon-TOKEN.log`。

Android 原生 Java 控件与前台服务负责界面和进程生命周期；Rust 负责参数、身份、请求文件归属、并发和 Frida 会话；内置 JS/Lua 调用原有金蟾方法。无桌面 Python、Node 或独立 frida-server 常驻要求。

目前接入候选查询、刷新、生成、归还。未接入奖励领取、升星、升阶或自动刷词条；已有候选中未出现炼化双忽视混乱，界面不能证明服务器允许重复词条。

“查询 / 刷新”在没有候选时查询，已有有效候选时刷新炼化。已去掉助手生成入口的单件限制，但当前 DHXY 金蟾入口在保留已有装备时返回“请先归还当前装备”；测试未新增装备、未扣普通仙玉。多件生成尚未实现。归还仍要求唯一装备 UID，不能在多件目标不明确时执行。候选内容用固定顺序比较，避免 JSON 对象字段顺序变化造成误拒绝。

## 构建与验证

使用现有 JDK 17、Android SDK 35、NDK 27.2.12479018、Rust `x86_64-linux-android` 与工作区 `.scratch/frida-core-devkit-17.17.0-android-x86_64`。设置 `JAVA_HOME`、`ANDROID_HOME` 后执行 `gradlew.bat assembleDebug`。`preBuild` 调用 `build.ps1` 构建 Rust worker；native executable 解包为 `libjinchan_worker.so`。

worker `--self-test` 只验证本地解析等逻辑，不发送游戏请求。常驻模式为 `--serve FILES_DIR GAME_PACKAGE CONNECTION_TOKEN`；连接状态与心跳使用原子状态文件，操作请求为十行私有文件，结果按独立 nonce 绑定。该内部协议不表示服务器支持任何未验证功能。

生成包位于 `app/build/outputs/apk/debug/app-debug.apk`；另存交付包和 SHA-256。构建或签名通过不代表连接保持、界面和服务器操作完整验收，实际证据记录在项目 `PROJECT_STATUS.md`。
