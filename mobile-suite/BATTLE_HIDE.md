# 战斗跳过：隐藏战斗画面

## 功能边界

「跳过战斗」与「隐藏战斗画面」在同一页面中分别设置。跳过默认开启，隐藏默认关闭，保留旧版本习惯；已有隐藏偏好继续保留。设置只对下次启动生效，运行及清理未确认期间两个开关都不能更改，共用启动、暂停与停止按钮。

| 跳过战斗 | 隐藏战斗画面 | 启动后的行为 |
| --- | --- | --- |
| 开 | 关 | 原有跳过流程，显示战斗画面 |
| 关 | 开 | 只隐藏画面，战斗由原客户端正常处理 |
| 开 | 开 | 跳过与隐藏同时运行 |
| 关 | 关 | 不启动服务工作进程，提示至少开启一项 |

隐藏部分控制战斗根节点与地图菜单的显示，并附带切图诊断。隐藏开启时透明观察发送调用和已存在的 `65505` 进入地图处理入口；不去重或拦截原来的行动/播放完成通知，不修改自动战斗状态，不执行跳过、动画加速或补发动作；只隐藏时暂停与停止也不发送恢复自动状态指令。原客户端仍按自己的战斗流程执行，角色是否自动出招取决于游戏自己的设置。跳过开启时继续沿用原有跳过流程。隐藏画面不意味着服务端退出战斗，也不能证明战斗中其他操作会被服务端接受。

两项设置通过单一原子配置发布并在每次运行时冻结，tick 与 stop 使用同一组值。旧配置缺少跳过选项时按开启兼容；新的双选项配置损坏时必须在连接游戏前拒绝，不静默开启跳过。

两个选项都关闭也保留停止和「核查旧任务」入口。手动核查只确认旧任务状态，不自动启动、不替用户勾选选项；拒绝本次启动不会覆盖旧任务的未确认记录。

入战前保存地图菜单布局，原处理完成后保存战斗菜单布局及根节点可见性，再隐藏战斗根节点并显示地图菜单。启动时如果已经在战斗中，等待下一场取得完整快照。自然结束保留客户端自己的界面恢复；暂停、停止和租约退出必须处理当前隐藏画面的恢复。恢复失败不得据此报告清理完成。

## 日志与排查

视觉诊断与原有选敌、动作日志分别保存。页面提供复制入口，实际启用状态与统计以 worker 的回报为准，勾选状态仅代表下次启动配置。

日志记录启用、开始隐藏、唯一回合变化、自然结束、恢复和异常原因；不记录封包正文、角色标识或内存地址。游戏侧采用有界轮转，应用侧同步有界尾部。日志写入失败不改变战斗处理。

### 切图观察

隐藏开启时，诊断使用透明发送包装：记录原调用的数字协议号，只有已核实的 `22568` 额外读取数字目标地图；不读取其他请求内容，不把未知协议称为“回家”。发送调用记录只说明客户端调用了发送入口，不证明数据到达服务端或操作被接受。只跳过且隐藏关闭时不增加这些观察。

`65505` 原处理入口存在时记录地图回包；不存在时记观察不可用，不中断隐藏功能。本地地图初始快照、后续本地地图变化与地图回包分开记录。每条事件附运行标识、顺序号、战斗编号、回合、战斗标志和可读的本地地图编号，缺失值写 `unknown`。战斗编号可在战斗结束后残留，必须结合战斗标志与后续同编号回合判断，不能只凭一个编号证明并存。

发送观察每秒限额并标明截断；日志仍为 64 KiB 加一份轮转、应用同步 64 KiB 尾部，所以缺记录不能证明没有发生请求。原发送与回包函数参数、返回值和异常保持透传，日志故障不改变原调用；停止仅恢复本会话仍持有的引用，其他模块替换入口时保持清理未确认。
