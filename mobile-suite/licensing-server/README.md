# 飘渺助手限时授权服务

这是独立的本机 Node.js 授权服务。它不会自动启动，也不会主动连接游戏或外部服务。需使用 Node.js 24 或更高版本；本项目不新增 npm 依赖。

## 启动与管理

首次在本机管理时，先安装 Node.js 24 或更高版本，再双击 `start.cmd`。窗口显示随机管理令牌并在服务监听就绪后打开本机管理页；复制令牌粘贴进页面。令牌仅在当前进程中生成，不写入文件或 URL；若启动前已设置 `PIAOMIAO_ADMIN_TOKEN`，启动器沿用它且不显示或修改它。关闭命令窗口会停止服务。程序员也可设置仅当前 shell 可见的管理令牌后用 `pnpm start`：

```powershell
$env:PIAOMIAO_ADMIN_TOKEN = node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
pnpm start
```

打开启动输出中的 `http://127.0.0.1:8787/`。管理页面要求输入同一个令牌，令牌只保留在当前页面内存，不放 URL、本地存储或代码。批量生成接受 1–500 个激活码与 1–3650 天；生成的激活码只在生成响应中显示一次，应立即复制并安全交付。管理端支持列表、停用、延长和解绑。授权数据库默认位于 `data/licenses.sqlite`，运行时会启用 WAL；保护数据库目录及其 `-wal`、`-shm` 文件，仅允许服务运行账户访问。Windows 可按实际服务账户用 `icacls` 收紧目录 ACL；不要把该目录放入共享或公开 web root。

```powershell
pnpm test
```

服务只监听 `127.0.0.1`。管理 API 使用 `Authorization: Bearer <PIAOMIAO_ADMIN_TOKEN>`，并检查本机来源；不能将 `/admin/` 路由发布或代理到公网。若需让 Android 客户端经公网使用，应在同机 HTTPS 反向代理中仅公开 `/v1/activate` 和 `/v1/verify` 两个精确 POST 路径，拒绝其它路径与方法；代理到本机 HTTP 后端 `127.0.0.1:8787`。客户端到代理必须使用 HTTPS。不得将管理路径配置为 catch-all 转发。服务自身不提供公网监听、TLS 或自动启动。

默认限流只按 TCP 对端地址分桶，完全忽略转发头。若同机反向代理转发客户端 API，且需按真实客户端 IP 分桶，可在启动前显式设置 `PIAOMIAO_TRUST_PROXY=1`。此模式只在 TCP 对端确为 loopback 时读取恰好一个有效的 `X-Real-IP`；缺失、重复、逗号列表或非 IP 值会让客户端请求返回 400。非 loopback 对端始终按 TCP 对端地址限流，并忽略 `X-Real-IP`。代理必须删除外部传入的同名头并自行覆盖为单个地址，不能追加；不要信任任意来源可直连的代理配置。管理 API 的来源与认证检查不使用转发头。

## 客户端 API

所有时间字段均为 Unix epoch 毫秒。产品字段固定为 `piaomiao-suite`。`installationId` 是客户端首次安装时用密码学随机源生成并持久保存的 256-bit base64url 安装凭证；卸载重装会形成新安装。客户端不得用设备标识替代随机凭证。客户端以请求开始时的 `elapsedRealtime` 记下单调时钟基点，将 `serverTime` 对齐到该基点，并据此计算不超过 `leaseSeconds` 的租约；Native worker 使用 `/proc/uptime` 与 `boot_id` 做同一启动周期内的单调计时，不能把可回拨的墙上时钟当授权时钟。

### `POST /v1/activate`

请求 JSON：`{ "code": "ABCD-EFGH-...", "installationId": "<持久的随机安装凭证>", "product": "piaomiao-suite" }`。激活码接受大小写字母与数字的 32 字符原码，也接受以 ASCII 空格或连字符分组的形式；其它字符不接受。Android 客户端可发送去掉连字符的形式。

成功返回 HTTP 200：`{ "sessionToken": "<随机会话令牌>", "expiresAt": 1800000120000, "serverTime": 1800000000000, "leaseSeconds": 120 }`。激活码是 160-bit 随机值，以 32 个 Base32 字符按四字符分组显示；数据库只保存去分组原码的 SHA-256。明文码仅在生成操作的响应中出现，数据库列表和后续管理接口不会回显原码；管理页面在生成时展示一次以便复制，运营方需及时安全保存。首次激活在 `BEGIN IMMEDIATE` 事务中绑定安装并开始计时；相同安装重试不会重置到期时间，其他安装返回 409。同一授权最多保留 8 个有效会话哈希；超过上限时按创建时间、token 哈希顺序淘汰最早会话。吊销和解绑会立即撤销该授权的全部会话；已失效、吊销或到期会话哈希会在后续请求/列表操作中清理。失效或未知激活码使用通用错误。

### `POST /v1/verify`

请求 JSON：`{ "sessionToken": "<激活返回值>", "installationId": "<原安装凭证>", "product": "piaomiao-suite" }`。成功返回与激活相同的时间字段。校验不轮换 token。服务端只存令牌哈希，客户端应按服务端 `serverTime` 判断授权，并在 `leaseSeconds` 到期前重新校验；该值是 `min(120, floor((expiresAt-serverTime)/1000))`，不足一秒时不给租约。参数错误返回 400；未知、吊销或解绑会话返回 401；授权到期返回 403 和 `{ "error": "授权已过期", "code": "LICENSE_EXPIRED" }`。客户端收到该明确到期响应时应保留 session token、停止旧租约且不延长旧租约，以便管理员续期后同一 token 可恢复验证。

未吊销授权的到期会话哈希保留至到期时间后 30 天；窗口内管理员续期后，原 session token 可继续验证，无需重新输入激活码。超过 30 天后会话哈希被清理；管理员续期后，用户需使用原激活码在原安装上重新激活以取得新 token。过期会话清理不删除授权记录，也不重置首次激活时间。

其它状态码：跨安装激活 409、已到期激活 403、请求过大 413、限流 429。请求体最多 8 KiB，服务限制 body 读取与 HTTP 请求等待时间；按来源 IP 与安装凭证限流，内存限流表有界。不得在访问日志或应用日志中记录激活码、会话 token 或安装凭证原文。

## 管理 API

这些接口仅用于本机管理页面，均需 Bearer 管理令牌，JSON POST：

| 方法与路径 | 用途 / 参数 |
| --- | --- |
| `GET /admin/list` | 最近 1000 条授权状态；`installationHint` 为已绑定安装凭证 SHA-256 的前 12 位大写十六进制，未绑定时为空字符串。可用于人工识别/筛选，不返回完整安装哈希、安装凭证或 session token |
| `POST /admin/generate` | `{ "count": 1, "durationDays": 30 }`，创建时一次性返回明文码 |
| `POST /admin/revoke` | `{ "id": "<list 中授权 id>" }`，立即拒绝后续校验 |
| `POST /admin/extend` | `{ "id": "<授权 id>", "days": 30 }`，激活后从 max(当前时间, 当前到期) 延长；未激活只调整初始时长 |
| `POST /admin/unbind` | `{ "id": "<授权 id>" }`，撤销旧会话并解除绑定，保留首次激活时间和原到期时间 |

解绑不会重置计时。解绑后的再次激活可由新安装绑定，但仍使用原到期时间；解绑和吊销会立即撤销该授权全部会话，即使随后管理员续期，旧 token 也不能恢复。已过期、吊销授权不能因删除记录而重获时长。吊销记录和到期记录应保留，勿手工删除来实现恢复或重置。

## 备份与恢复

在线备份使用 SQLite backup API/支持一致快照的 SQLite 工具；若只能复制文件，先正常停止服务并确认 SQLite 已关闭，再一起备份数据库及 WAL 状态。不得在服务运行中只复制主 `.sqlite` 文件。恢复前先停止服务，保存现有目录副本，再恢复一致快照到 `data/`，检查文件 ACL 后启动并核对授权列表。服务停止会令最长 120 秒的客户端租约失效或等待重新校验；磁盘故障、数据库损坏和备份间隔内签发的授权是运营方需要处理的数据恢复边界。

## 明确限制

服务端数据库是授权真值来源。客户端在无法访问服务时最多能依照最近一次成功响应使用不超过 120 秒的本地租约。任何可离线修改客户端的方案都不能抵抗本机管理员篡改时钟、代码或存储；本服务是本机管理端，朋友或其它设备要使用须由运营方部署 HTTPS 服务/代理并公开客户端 API，不能直接访问本机页面。部署方还须维护 HTTPS 证书、代理访问日志脱敏、备份和监控。服务不自动启动，也没有执行真实外部流量验收。
