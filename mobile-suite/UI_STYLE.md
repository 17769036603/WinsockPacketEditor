# APK UI 外观规范

本轮独立副本在用户授权的功能优化范围内补充设置页的完整版本名、构建号、授权模式、支持架构和“复制诊断信息”入口。设置内容允许滚动；侧栏、模块顺序、CompactUi 和原有按钮语义保持不变。诊断中的模块状态项按白名单只展示状态枚举与新鲜度；诊断同时包含完整版本、构建号、授权模式、ABI 和最近调度的受限摘要，不显示游戏身份、原始错误文本、激活码或授权凭证。定时任务行补充下次执行和最近结果，任务编辑方式保留。

## 目标与范围

本规范定义统一 APK 的视觉外观。以现有界面和排版为基准，只调整材质、颜色、描边、明暗和阴影；横屏方向、侧栏及模块顺序、顶部信息位置、控件尺寸与间距、页面内容、交互和状态含义均保持不变。不得为了呈现玻璃效果新增、删除、移动或重排控件，也不得改变 CompactUi 的缩放规则。

顶部不再有标题栏：模块名由侧栏选中项表达，内容区直接顶到状态栏下方，把整条顶栏的高度让给页面。目标选择与授权入口在侧栏末尾的「系统设置」页，模块状态仍由侧栏表达（无障碍描述保留完整状态）。目标游戏、授权状态、版本名与构建号统一在设置页查看和操作。

侧栏每项为 11sp 模块名、项高 42dp、项间距 3dp，八个模块项（角色速度、战斗跳过、战斗面板、自动找星、自动BOSS、战斗快进、金蝉装备、暗雷遇敌）在首屏内全部可见；导航列表单独滚动，「定时任务」与「系统设置」两个入口固定贴在侧栏底部（「定时任务」在上，34dp 高、10sp 文字、14dp 时钟图标；「系统设置」在下，上方 1dp 分隔线，规格相同；两者选中时都只加青绿描边与浅填充、不加柔光，比模块项更轻，不参与模块状态显示），不跟随列表滚动，也不会悬在列表中间。选中项在强调玻璃底上叠一条左侧 2dp 青绿指示条。每项左侧有 15dp 单色矢量图标（`ic_nav_speed/fast/skip/panel/equip/thunder/star/boss`），选中为浅色、未选中为次要文字色，图标不改变条目高度与侧栏宽度。状态文字为非空闲时才显示，格式为"● 等待中/运行中/已暂停/清理中/错误/未确认"（8sp，配色依次为琥珀、绿、琥珀、琥珀、红、灰），已停止与尚未读取不占位。战斗跳过支持暂停：暂停只停发指令、保留钩子与租约，状态写 `state=paused`，侧栏显示「已暂停」。

顶栏底部为两层柔和阴影（约 3px），内容滚动时与下方内容保持层次。页面底色、系统栏色、内容网格（左右 16dp、上下 12dp）、圆角三档（控件 8dp、容器 12dp、胶囊 20dp）、按钮两档高度（48dp/40dp）与字号层级（页面标题 18sp、顶栏标题 14sp、分组与正文 12sp、按钮 13sp、辅助 10sp）统一定义在 `GlassSkin` 的公共变量里，页面不再各写一套。操作按钮语义色同样共用变量：`ACTION_START` 为青绿 `rgb(51,147,131)`、`ACTION_STOP` 为红 `rgb(206,94,94)`；停止红取更高饱和度，否则与深蓝底混合后接近中性暗灰、与禁用态难以区分。`ACTION_START`/`ACTION_STOP` 故意不加 `final`——加了会被内联进各模块，改色后旧字面量仍留在已编译的调用方里。

页面底色不再用纯色填充：`GlassSkin.page()` 提供 `#0E1F2B → #0A131B` 的极轻对角渐变，所有页面统一改用该 drawable，避免整屏"死黑"。玻璃表面在原有渐变填充与发丝描边之外，增加顶部 1dp 内高光（`HIGHLIGHT`，白 10%），只改观感、不占布局。主操作按钮（`GlassSkin.action`）改为实心青绿 `#41B5A1 → #2F8B7B`；所有"开始/启动"类按钮走 `GlassSkin.actionTinted(..., ACTION_START)`，统一渲染为实心青绿渐变 `#52BDA9 → #339383`（按下 `#41A794 → #2C7F72`，禁用仍为中性暗色），停止类按钮沿用 `TINT_RATIO = 0.72` 保留红色语义。侧栏选中项在强调玻璃上再叠一层 12% 青绿柔光与 2dp 左侧指示条。侧栏图标重绘为更简洁的几何剪影（速度仪表为 2.2dp 描边圆环+指针，其余为实心剪影），槽位仍为 15dp。多选状态（如自动找星的星级预设、其他已选胶囊）用 `GlassSkin.selectedDanger()` 的红色实心标记（`#D4514F → #A53232`、浅红描边、白字），与青绿的"选中/当前页"区分开，一眼能看出哪些已被勾选。

停止按钮的红只在**可用**时出现，禁用态一律用中性暗色填充加暗化文字。各页空闲时是否禁用停止由模块语义决定，属有意差异：角色速度、战斗面板、自动找星在空闲时禁用（没有需要停止或恢复的对象）；暗雷遇敌、战斗跳过、战斗快进始终可点，因为停止同时承担旧的 hook 与绑定清理、恢复核验职责。不要为了"看起来统一"把这些页改成同一种可用性。

主/次操作按尺寸区分，颜色语义保持不变：主操作 48dp 高、13sp、占满内容宽度；次操作 40dp 高、12sp。并排按钮的行内让两种高度垂直居中。角色速度、暗雷遇敌、战斗跳过、战斗快进、战斗面板、自动找星六页已按此执行；金蝉装备页的六个操作没有明确主次，保持原高度不动。

交互反馈保持克制、只动透明度与阴影：切换模块页面时 120ms 淡入；按钮按下时去掉底部阴影层，表面"下沉"一层；侧栏处于等待中的模块，其状态文字做 900ms 往返的透明度呼吸（0.55～1.0）。不使用位移、缩放、光晕或霓虹类动画。

## 视觉方向：克制的磨砂玻璃

采用第一种方案的 BlurView 式磨砂观感：在现有深色界面上，为已有控件和表面增加轻微的半透明与局部背景虚化，整体保持深海军蓝底色和青绿强调色。效果应显得轻、清晰、克制，不把页面做成明亮的玻璃面板。

- 仅在现有表面区域体现磨砂材质，例如当前选中的侧栏项、顶部状态或选择控件、输入框和操作按钮；不额外添加卡片或容器。
- 玻璃表面使用带蓝色调的半透明深色填充。背景虚化范围限制在对应表面后方，虚化轻微；文本、图标、输入值和状态提示保持清晰。
- 保留现有青绿作为强调色。描边细而低调，仅在已有的选中、焦点或强调状态上稍加强度。
- 阴影柔和、范围小；允许极轻的表面高光，不使用强光晕、霓虹边缘或彩虹折射。
- 确保文字和数值在不同背景上仍有足够对比度。禁用、运行中、错误和权限提示继续使用清楚且一致的状态表达。

## 实现约束

BlurView 是材质效果参考，不指定必须采用某个 GitHub 库，也不要求为本规范新增依赖。虚化只针对应用自身可控的背景内容；不能实现可靠虚化时，使用半透明深色填充、细描边和柔和阴影维持相同观感，不得降低内容可读性。任何后续实现仍须遵守上述布局、交互和功能边界。

## 视觉验收

在相同页面和窗口尺寸下对照现有界面：导航、标题、状态、目标速度输入框和操作按钮的位置及尺寸不变；页面信息与操作方式不变；玻璃质感只作用于已有表面，正文与控件标签清晰可读，深色底色和青绿色强调色保持统一。
